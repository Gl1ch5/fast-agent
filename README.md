# ⚡ fa — fast agent

**Кодинг-агент в одном файле. Без зависимостей. Без лишних действий.**

`fa.ts` · один файл · 0 зависимостей · полноэкранный TUI · Windows / Linux / macOS

</div>

---

Современные агенты огромные. На простую просьбу вроде «сделай игру в одном HTML» они
читают полпроекта, строят планы, создают README и тесты и перепроверяют сами себя.

`fa` делает только то, что попросили:

```
› сделай игру змейка в одном index.html
✓ Write index.html  created · 227 lines · 6.2 KB
● Создан index.html с игрой «Змейка» (стрелки/WASD, очки, рекорд, пауза).
  ✻ 19.0s · ↑3.7k ↓2.3k · 2 steps
```

Один вызов инструмента. Ничего лишнего.

## Точно по запросу

Системный промпт запрещает выходить за рамки просьбы: не запускать тесты, сборку и программу,
если об этом не просили; не создавать README, тесты и конфиги; не добавлять «улучшения»,
рефакторинг и зависимости; не придумывать требования. Имена, пути, библиотеки и способ решения
берутся ровно из запроса. На вопрос агент отвечает, а не правит файлы.

## Интерфейс

Полноэкранный TUI с анимациями:

- **подсказки команд** — набери `/`, и сразу появится список команд с описаниями
  (`↑↓` выбор, `Tab` дополнить, `Enter` выполнить);
- **каждое действие на виду** — у каждого инструмента живая карточка со спиннером и временем,
  после завершения она становится строкой `✓`/`✗` с итогом;
- **парсер shell-команд** — длинная команда показывается коротко и понятно:

  ```
  cd app && npm install express cors 2>&1 | tail -5     →  in app · npm install express cors | tail
  git add -A && git commit -m "fix: crash" && git push  →  git add → git commit "fix: crash" → git push
  cat > index.html <<'EOF' …                            →  write index.html (heredoc)
  ```

  Пока команда работает, видны последние строки её вывода, а если в выводе есть прогресс
  (`45%`, `[3/10]`), рисуется полоса `━━━━━━╸──── 55%`;
- **рассуждения модели** бегут в строке статуса и сворачиваются в `∴ Thought for 4s`;
- статус с переливающимся текстом, таймером и счётчиком токенов; `PgUp`/`PgDn` листают историю.

## Почему он быстрый

| | |
|---|---|
| 🎯 **Короткий системный промпт** | Чёткие правила: действовать сразу, новый файл писать целиком одним вызовом, ничего не перечитывать, лишних файлов не создавать |
| 📂 **Список файлов уже в контексте** | Модель сразу видит содержимое папки, поэтому не тратит шаг на `ls`. Пустая папка — сразу пишет код |
| 🧰 **Всего 4 инструмента** | `write`, `edit` (сразу несколько правок), `read` (файлы и папки), `shell` |
| ⚡ **Параллельное выполнение** | Независимые вызовы инструментов идут одновременно, вызовы к одному файлу — по очереди |
| 💾 **Кэширование промпта** | Точки кэша Anthropic на системном промпте и последнем сообщении; у OpenAI-совместимых API кэш автоматический |
| ✂️ **Компактные ответы инструментов** | Вывод обрезается, результат записи — одна строка вместо эха файла |
| 🧠 **Регулятор `/think`** | Уровень рассуждений `low` … `max`, или `auto` — по умолчанию у провайдера |
| 🚀 **`/fast`** | Fast mode у Anthropic (Opus, вывод до ~2.5× быстрее) |
| 📡 **Стриминг всего** | Текст, рассуждения, живой счётчик байт, пока модель пишет файл |

## Установка

Нужен **Node.js 22.18+**: он запускает `.ts` напрямую, без сборки.

Одна команда: скачает `fa`, добавит его в PATH и при необходимости поставит Node.js (через winget на Windows или Homebrew на macOS).

**Windows (PowerShell):**

```powershell
irm https://raw.githubusercontent.com/gl1ch5/fast-agent/main/install.ps1 | iex
```

**Linux / macOS:**

```bash
curl -fsSL https://raw.githubusercontent.com/gl1ch5/fast-agent/main/install.sh | sh
```

Без установки: `node fa.ts`. Обновление: запусти ту же команду ещё раз.

Поставить версию из другой ветки (например, ещё не влитого PR):

```powershell
$env:FA_REF='имя-ветки'; irm https://raw.githubusercontent.com/gl1ch5/fast-agent/имя-ветки/install.ps1 | iex
```

```bash
curl -fsSL https://raw.githubusercontent.com/gl1ch5/fast-agent/имя-ветки/install.sh | FA_REF=имя-ветки sh
```

## Быстрый старт

```bash
cd my-project
fa                                   # интерактивный режим
fa "добавь тёмную тему"              # сразу выполнит задачу и останется в чате
fa -p "сделай tetris в index.html"   # выполнит и выйдет (для скриптов)
cat log.txt | fa -p "почему падает?" # stdin добавляется к промпту
```

При первом запуске откроется мастер настройки (повторить: `/setup`):

1. **провайдер** — из списка или свой (OpenAI- или Anthropic-совместимый); ключ берётся
   из переменной окружения или вводится в мастере;
2. **модели** — список с поиском, отмечаешь пробелом только нужные (например, две);
3. **effort** — уровень рассуждений.

Потом `/model` переключает между выбранными моделями, `/models` добавляет или убирает их.

## Провайдеры

Готовые пресеты (ключ берётся из переменной окружения или через `/key`):

| провайдер | переменная |
|---|---|
| `anthropic` | `ANTHROPIC_API_KEY` |
| `openai` | `OPENAI_API_KEY` |
| `openrouter` | `OPENROUTER_API_KEY` |
| `gemini` | `GEMINI_API_KEY` |
| `groq` | `GROQ_API_KEY` |
| `cerebras` | `CEREBRAS_API_KEY` |
| `deepseek` | `DEEPSEEK_API_KEY` |
| `xai` | `XAI_API_KEY` |
| `mistral` | `MISTRAL_API_KEY` |
| `ollama`, `lmstudio` | локальные, без ключа |

**Свой провайдер** — любой OpenAI- или Anthropic-совместимый API:

```
/provider add my http://my-server:8080/v1 sk-xxxx
/provider add proxy https://my-proxy.example.com sk-xxxx anthropic
```

После добавления `fa` сразу загружает список моделей провайдера и даёт отметить нужные.

## Выбор модели

- `/model` — список выбранных моделей с поиском, текущая отмечена `●`
- `/model my/some-model` — выбрать сразу, без списка
- `/models` — добавить или убрать модели: выбираешь провайдера, `Enter` ставит или снимает
  галочку у модели (`Ctrl+A` — все), строка `✓ Save` вверху списка сохраняет

## Аккаунт и синхронизация

`/login` (или `L` на экране приветствия) — вход по логину и паролю; если аккаунта ещё нет,
`fa` предложит его создать. После входа провайдеры, API-ключи, список моделей, текущая модель,
effort, fast и safe хранятся на сервере синхронизации: на новой машине достаточно войти —
всё настроено. Каждое изменение отправляется сразу, при запуске `fa` подтягивает более новые
настройки. Сервер — `https://grzxk.ru/fa-sync` (свой можно указать: `FA_SYNC_URL`);
его код — `server/fa-sync.ts`, один файл без зависимостей:

```bash
FA_SYNC_PORT=8771 FA_SYNC_DATA=/var/lib/fa-sync node server/fa-sync.ts   # за nginx с HTTPS
```

## Команды

| команда | что делает |
|---|---|
| `/model [поиск]` | выбрать модель |
| `/models` | добавить или убрать модели |
| `/setup` | мастер: провайдер, модели, effort |
| `/think [уровень]` | `auto` · `low` · `medium` · `high` · `xhigh` · `max` |
| `/fast` | fast mode у Anthropic |
| `/provider` | список провайдеров · `add <имя> <url> [ключ] [openai\|anthropic]` · `rm <имя>` |
| `/key [провайдер ключ]` | сохранить API-ключ (без аргументов — через диалог) |
| `/safe` | спрашивать подтверждение перед каждой shell-командой |
| `/undo` | откатить изменения файлов от последнего запроса |
| `/clear` | новый диалог |
| `/login [логин]` | войти в аккаунт (или создать) и синхронизировать настройки |
| `/sync` | синхронизировать сейчас |
| `/logout` | выйти из аккаунта |
| `/update` | обновить `fa` до последней версии |
| `/help`, `/exit` | справка, выход |

## Безопасность: всё в одной папке

- `read` / `write` / `edit` **жёстко заблокированы** внутри рабочей директории (с учётом симлинков). Попытка выйти за её пределы получает отказ.
- `shell` запускается в рабочей директории без stdin, с таймаутом и убийством всего дерева процессов. Для подтверждения каждой команды есть `/safe` или `--safe`.
- `/undo` откатывает все изменения файлов от последнего запроса.

На Windows `shell` — это PowerShell с выводом в UTF-8. Другую оболочку задаёт `FA_SHELL` (например, `FA_SHELL=bash` для Git Bash).

## Конфиг

`~/.fa/config.json` (путь меняется через `FA_HOME`). Создаётся сам, можно править руками:

```json
{
  "provider": "anthropic",
  "model": "claude-opus-5-5",
  "models": ["anthropic/claude-opus-5-5", "openrouter/qwen/qwen3-coder"],
  "effort": "auto",
  "maxTokens": 32000,
  "providers": {
    "my": { "type": "openai", "url": "http://host:port/v1", "key": "sk-..." },
    "openrouter": { "key": "sk-or-..." }
  }
}
```

Если в папке проекта есть `AGENTS.md` или `CLAUDE.md`, они попадают в системный промпт.

## Опции CLI

```
fa [options] [prompt]
  -p, --print        выполнить и выйти
  -m, --model P/M    провайдер/модель
  -e, --effort LVL   auto | low | medium | high | xhigh | max
  -C, --cwd DIR      рабочая директория
      --safe         подтверждать shell-команды
      --update       обновиться до последней версии и выйти
```

## Обновление

Версии до 0.2.1 команды `/update` не знают — обнови их, запустив команду установки ещё раз
(ссылка именно на `main`, не на `HEAD`). Дальше — `/update`.

`/update` внутри `fa` или `fa --update` скачивает свежий `fa.ts` и заменяет текущий файл;
после обновления `fa` предложит перезапуститься. Раз в 12 часов `fa` тихо проверяет новую
версию и, если она есть, показывает `↑ 0.x.y · /update` в нижней строке.

## Разработка

Исходники разбиты на маленькие модули в `src/`, а `build.ts` склеивает их в один `fa.ts`
(именно его скачивают установщики). Сборщик без зависимостей: модули упорядочиваются по
импортам, локальные импорты и `export` убираются, импорты `node:` объединяются.

```
src/
  main.ts           точка входа: режим -p или TUI
  env.ts            аргументы CLI, ROOT        config.ts   конфиг, провайдеры
  prompt.ts         системный промпт           setup.ts    мастер, выбор моделей
  commands.ts       слэш-команды               update.ts   самообновление
  sync.ts           аккаунт и синхронизация настроек
  agent/            цикл агента, стриминг, состояние
  api/              Anthropic, OpenAI-совместимые, /models, HTTP
  tools/            write, edit, read, shell, песочница
  shell/            парсер команд, разбор прогресса
  ui/               экран, отрисовка, ввод, модальные окна, карточки, цвета
```

```bash
node src/main.ts        # запуск прямо из исходников
node build.ts           # собрать fa.ts (и проверить, что он запускается)
node build.ts --check   # CI: fa.ts соответствует src/
```

Имена верхнего уровня должны быть уникальны во всём `src/`: сборка упадёт, если найдёт дубль.
